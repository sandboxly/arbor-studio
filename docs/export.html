Exporting

ArborStudio exports trees as GLB (binary glTF 2.0), as OBJ with an MTL material file, or as JSON tree data. GLB and OBJ open in Unity, Unreal, Godot, Blender and most other 3D tools. All exports use metres, with Y pointing up.

Exporting a tree

  1. In the File menu, or the Export menu in the toolbar, choose which levels of detail to include: Include LOD0–3 and Include billboard LOD.
  2. Choose Export GLB, Export OBJ or Export tree data (JSON). ⌘E (Ctrl+E on Windows and Linux) exports GLB.
  3. Choose a file name and folder. The status bar lists the files that were written.

Exports contain the tree as it is shown, with node edits, pruning and the current season. Hidden generators (check box off) are left out.

Wind data

GLB exports store two wind weights for every vertex in the second texture coordinate set (TEXCOORD_1, often called UV2):

  • x: branch sway, from 0 at the ground to 1 at the tips of the crown.
  • y: leaf flutter, from 0 to 1.

A vertex shader can move each vertex by these weights with the wind direction and strength. The wind settings of the tree are stored in the file's extras. Welded branch joints blend their weights into the parent, so the joint does not tear when the tree moves.

Vertex colours

GLB exports contain a vertex colour (COLOR_0) with the material colour, the per-leaf colour variation, the autumn colours and the baked ambient occlusion. Multiply it with the colour texture in your material to get the look of the viewport.

Growth animation

With Include the growth in exports on (Properties › Growth), GLB files carry the growth from a sprout to the mature tree as morph targets with one clip per stage, OBJ exports add one file per stage and JSON adds the growth timing. See Growth animation.

Exporting variations

A forest needs many individuals of one species. Export variations grows the tree with several seeds and writes one file per individual.

  1. Set the number of variations next to Variations in the toolbar's Export menu (or the File menu on Windows and Linux).
  2. Choose Variations as GLB… or Variations as OBJ… and select a folder.

The files are named <Tree>_v01, <Tree>_v02 and so on, and their meshes carry the same suffix. The first variation uses the current seed, and each following one the next seed. The level-of-detail options apply to every file. Node edits are not applied to variations.

Using the export in an engine

The steps below describe the usual import route. Menu names differ between engine versions.

Unity

  • Copy the OBJ with its MTL and textures, or the GLB, into the project's Assets folder. GLB requires a glTF importer package, for example glTFast.
  • Use the _LOD meshes in a LOD Group component, if the importer does not create one.
  • Leaves need a material with alpha clipping and both faces rendered.

Unreal Engine

  • Import the GLB or OBJ through the Content Browser. Unreal uses centimetres; set the import scale if the tree arrives at 1/100 of its size.
  • Choose Unreal (UCX_) as collision naming before exporting, so the collision hulls become the mesh's collision.
  • Assign LOD1 to LOD4 as levels of detail of the LOD0 static mesh.

Godot

  • Copy the GLB into the project. Godot imports it as a scene.
  • Choose Godot (-convcolonly) as collision naming before exporting, so the collision hulls become collision shapes.
  • Switch between levels with the visibility range settings of each mesh instance.

JSON tree data

The JSON export is for custom engines and tools that build their own meshes. It contains:

document
All generator, material and tree settings, enough to grow the tree again.
skeleton
Every stem as a list of points with a radius per point, and every leaf with position, direction from base to tip, normal and size.
collision
The collision capsules, each with two end points and a radius.
stats
Stem, leaf, vertex and triangle counts and the size of the tree.

The file also states its units (metres) and up axis (Y).
